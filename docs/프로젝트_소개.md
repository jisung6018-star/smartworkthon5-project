# 팩트마케터 for 티링크 — 프로젝트 소개

이 문서는 이 사이트가 무엇이고, 무슨 기능이 있고, 어떻게 만들어졌는지를 한곳에 적은 것입니다. 수치는 저장소의 `README.md`와 같은 값을 씁니다.

## 한 줄 소개
티링크의 제품 자료와 설치 현장 사진 한 장으로, 고객마다 다른 홍보 콘텐츠를 만들고 게시 전에 숫자와 조건을 자료와 대조하는 티링크 전용 마케팅 도구입니다.

## 무엇을 위한 사이트인가
제5회 AI 스마트워크톤(2026-11-20) 트랙 A의 과제는 다음 문장입니다.

> "티링크의 제품과 기술적 차별점을 AI가 분석하고, 현장 사진과 제품 정보만으로 고객의 관심을 끌 수 있는 홍보 콘텐츠를 자동 생성하는 마케팅 솔루션을 개발해 주세요."

- **티링크**는 통화 녹취 서버와 통화 기록 관리 솔루션(티링크 비즈레코딩)을 기업·학교·콜센터에 공급하는 회사입니다.
- **받은 자료**는 문서 6종(제안서, CRM 매뉴얼, 휴대폰 버전 매뉴얼, PC폰 버전 매뉴얼, 회사소개서, 블로그 가이드라인)과 티링크 홈페이지 9쪽입니다. 모두 합쳐 자료 15개, 123쪽입니다.
- **현장 사진**은 티링크 홈페이지 설치 사례 페이지의 사진 15장입니다. 고객명은 홈페이지에 가려진 이름 그대로만 씁니다.
- 원본 문서와 사진 파일은 이 저장소에 넣지 않았습니다. 분석 결과(`data/`)와 만들어진 카드뉴스 이미지만 들어 있습니다.

풀려는 문제는 세 가지입니다. AI에게 홍보 글을 맡기면 자료에 없는 숫자가 섞이고, "99%" 같은 수치에서 조건이 빠지고, 누구에게나 같은 말을 합니다.

## 사용하는 사람과 흐름
사용자는 티링크의 마케팅·영업 담당자입니다. 화면은 세 개의 탭입니다.

1. **분석** — 탭을 열면 AI가 자료에서 뽑은 기술적 차별점, 시장 4종의 비교, 구매 결정자 3명, 자료마다 값이 다른 수치가 나옵니다. "근거 보기"를 누르면 출처 쪽과 원문 구절이 나옵니다.
2. **콘텐츠** — 현장 사진 1장, 목표 시장, 구매 결정자, 콘텐츠 종류를 고르고 "콘텐츠 만들기"를 누릅니다. 결정자마다 카드뉴스 4장과 원고가 나옵니다. 저장된 결과에는 생성 시각이 표시됩니다.
3. **검수와 승인** — 원고마다 "게시할 수 있습니다" 또는 "수정이 필요합니다 · 막힌 곳 n건"이 한 줄로 나옵니다. 문제 문장은 원고에서 색으로 표시되고, 오른쪽에 이유와 원문이 나옵니다. 막힌 곳이 없을 때만 승인 버튼이 켜지고, 승인한 원고만 내려받을 수 있습니다. 승인 뒤에 원고를 고치면 승인이 풀립니다.
4. **요청으로 고치기** — 검수 탭의 "AI에게 고쳐 달라고 하기" 칸에 "더 짧게", "표지 제목을 질문형으로"처럼 글로 적으면 AI가 고치고 바로 다시 검수합니다.

## 기능 목록

### 핵심 (1단계 기획서의 범위)
- 자료를 사실 카드로 정리: 사실마다 출처 파일·쪽과 원문 구절을 붙이고, 그 구절이 그 쪽에 있는지 프로그램이 대조
- 자료 간 불일치 찾기 (예: 학교 도입 수 200여 개와 150+, 99%의 '인터넷 전화' 조건)
- STP · ICP · JTBD · USP 분석과 구매 결정자 3역할(경영진 · 실무 관리자 · 전산 담당자). 항목마다 [확인된 사실] / [AI 추론] / [검증 필요] 표시
- 같은 사진 1장으로 결정자별 카드뉴스 4장과 네이버 블로그 원고 생성
- 프로그램 검수: 숫자, 조건, 고객명, 필수 키워드 3개, 티링크 블로그 가이드라인 미션 11개, 광고 표기
- 승인한 것만 내려받기, 쓰지 않을 표현 등록(금지어·대체어 사전)
- 정해 둔 오류를 일부러 넣어 검수가 잡는지 재는 시험

### 추가 (기획서에 없던 것)
- 시장 4종(콜센터 · 교육기관 · 의료 · 무역·물류)의 적합성 비교와 시장별 설득 전략. 근거가 없는 평가 기준은 '판단 보류'
- 도입 사례, 영업 이메일 원고. 도입 사례 자료가 없는 시장은 "신규 시장 제안"으로 표시
- 요청으로 고치기 (원고와 카드뉴스)
- 소개 사이트 (https://factmarketer-web.vercel.app/)

## 어떻게 만들었나
대회 당일 하루 동안 아래 순서로 만들었습니다.

1. **1단계 기획서 제출.** "현장 사진으로 고객별 설득 전략을 만드는 B2B 마케팅 AI"라는 기획을 냈고, AI 심사에서 평균 84.6점과 지적 7가지(범위가 넓다, 한정어 검증의 경계, 검출률·오탐률 측정 등)를 받았습니다.
2. **자료를 쪽 단위로 읽기.** 제공 문서와 홈페이지를 파일·쪽 단위로 나눠 AI가 사실을 뽑게 하고, 인용 구절이 실제로 그 쪽에 있는지 프로그램으로 대조했습니다. 사실 카드 281개와 자료 간 불일치 8건이 나왔습니다. 기획서에 적었던 '암호화 방식'은 용도가 다른 두 방식이라 불일치가 아니어서 뺐습니다.
3. **결정자별 콘텐츠와 코드 검수.** 사진 1장으로 3역할의 카드뉴스와 블로그를 만들고, 숫자·조건·고객명·가이드라인을 프로그램이 검사하게 했습니다.
4. **팀원과 GitHub 이슈로 설계 토론.** 설계 변경과 반박을 이슈로 주고받았습니다. 이 과정에서 범위가 시장 4종 × 콘텐츠 4종으로 넓어졌습니다. 현장 사진 진단 기능은 만들었다가 설계 변경으로 뺐습니다.
5. **화면과 카드뉴스를 다시 디자인.** 팀 안에서 "AI 티가 나고 사람이 읽기에 불필요한 부분이 많다", "홍보물이 사진에 글귀만 붙인 수준이다"라는 지적이 나왔습니다. 화면은 상태 한 줄과 '고칠 곳' 중심으로 바꾸고 근거는 눌렀을 때만 보이게 했습니다. 카드뉴스는 사진을 액자에 넣고 큰 숫자 옆에 출처를 적는 디자인 틀로 다시 그렸습니다.
6. **자체 심사.** 서로 다른 관점(실제 작동, 마케팅 실무, 기획 대비 구현과 측정의 정직성)의 검토자 3명에게 2단계 채점 항목으로 평가를 맡겼습니다. 평균 84점대였고, 검출률 시험이 스스로 만든 오류를 스스로 잡는 시험이라는 점, 내부 표시가 결과물에 남는 점 등이 지적됐습니다.
7. **버그 수정과 보강.** 검수기가 문장을 "다", "요" 뒤에서 잘못 잘라 정상 원고 2편을 막던 버그를 찾아 고쳤습니다. 숫자와 단위를 함께 맞추는 검사 등도 만들어 시험했습니다. 저장소에 들어 있는 검수기의 현재 수치는 `README.md`를 기준으로 봐 주세요.
8. **한계를 그대로 기재.** 잘못 적었던 문장을 정정하고, 재지 못한 것과 놓치는 오류 유형을 `README.md`에 적었습니다.

## 역할 분담 원칙
- **AI**: 자료 읽기, 추천, 글쓰기
- **프로그램**: 숫자·조건·이름의 판정. AI를 쓰지 않으므로 같은 원고에는 항상 같은 결과가 나옵니다
- **사람**: 근거 없는 문장의 확인과 최종 승인

자료와 사진 속 문장은 지시가 아니라 데이터로만 다룹니다.

## AI를 어디에 썼나
- **Claude**: 사실 추출, 고객·시장 분석, 카드뉴스와 원고 쓰기, 요청으로 고치기, 현장 사진의 설치 형태 판독
- **Gemini**: 같은 사진을 따로 읽어 설치 형태가 일치하는지 교차 확인 (일치 여부는 프로그램이 비교)
- **개발 과정**: AI 코딩 도구(Claude Code)로 코드를 작성하고 시험했습니다. 설계와 지적은 팀원 두 명이 GitHub 이슈와 대화로 정했습니다.

검수(숫자·조건 판정, 시험)에는 AI를 쓰지 않습니다.

## 실제로 잰 값
| 항목 | 값 |
|---|---|
| 읽은 자료 | 15개, 123쪽 |
| 사실 카드 | 281개. 인용 구절 281개가 모두 그 쪽에 있음(구절의 존재만 대조) |
| 자료 간 불일치 | 8건 (코드 판정 6건, AI가 낸 후보 2건) |
| 시장 적합성 | 콜센터 1순위(4.0점), 교육기관 2순위(3.9점). 의료와 무역·물류는 추천 보류 |
| 사진 판독 | 15장 중 13장에서 두 모델의 설치 형태가 일치 (1장은 둘 다 '판독 불가') |
| 만든 콘텐츠 | 8개 조합에서 카드뉴스 96장, 원고 54편 (블로그 21 · 도입 사례 12 · 영업 이메일 12) |
| 검수 | 54편 모두 차단 없음 |
| 정해 둔 오류 유형의 회귀 시험 | 819건 중 819건 검출 (검수 규칙을 만든 쪽이 만든 오류) |
| 따로 쓴 오류 | 독립된 검토자 두 명이 쓴 68개 중 처음 17개, 규칙 보강 뒤 56개 검출 (검수기를 고치기 전의 값) |
| 오탐률 | 사실 카드 문장 258개 중 5개 (1.9%). 숫자가 든 문장만 보면 13.2% |
| 표현 변형 | '약 3,000석', '3천 석'처럼 바꿔 쓴 67문장 중 잘못 걸린 것 0건 |
| 생성 시간과 비용 | 사진 1장으로 3역할 카드뉴스 12장과 블로그 3편에 74~93초, AI 비용 약 1,000~1,200원 |

각 수치가 뜻하는 범위와 한계는 `README.md`의 표에 적혀 있습니다. 시험은 `python -X utf8 check_all.py`로 다시 돌릴 수 있습니다(AI 호출 없음).

## 한계와 다음 단계
- 숫자가 없는 지어낸 주장은 프로그램이 판정하지 못합니다. 근거가 붙지 않은 문장을 "읽어 볼 문장"으로 사람에게 넘깁니다.
- [확인된 사실] 표시는 근거 카드 번호가 붙어 있고 숫자가 맞는다는 뜻입니다. 그 카드가 문장의 내용을 뒷받침하는지는 검사하지 않습니다.
- 카드의 "확인 필요" 배지와 "출처" 표시, 원고의 `[확인 필요]` · `[이미지: …]` · `[직접 사용 후 작성 …]` 자리는 담당자가 채우거나 지워야 게시할 수 있습니다.
- 콘텐츠가 고객의 관심을 얼마나 끄는지, 수작업보다 시간이 얼마나 줄어드는지는 재지 않았습니다.
- 검수 규칙의 일부(필수 키워드, 미션 11개, 조건어)는 티링크 가이드라인에 맞춰 코드로 쓰여 있습니다. 다른 회사에 쓰려면 이 규칙도 다시 써야 합니다.

다음 단계로 생각하는 것:
- 자료마다 다른 수치를 담당자가 한 번 확정하면 모든 콘텐츠가 그 값만 쓰게 하기
- 검수용과 게시용 결과물을 나눠 내보내기
- 문장과 근거 카드의 내용이 맞는지 확인하는 검사
- 티링크 담당자가 직접 써 보고 작성·검수 시간을 재기

## 저장소 구조 한눈에
```
app.py                  웹 화면 (분석 · 콘텐츠 · 검수와 승인)
ingest.py, collect.py   자료와 홈페이지를 쪽 단위로 읽기
build.py, build_industry.py, make_content.py   분석 → 시장 전략 → 콘텐츠 생성
check_all.py            저장된 원고 전체 재검수와 시험 (AI 호출 없음)
build_site.py           소개용 정적 사이트 만들기
kit/analysis.py         사실 카드, 원문 대조, 불일치, 고객·시장 분석
kit/content.py          사진 판독, 카드뉴스 · 블로그 · 도입 사례 · 영업 이메일
kit/cardnews.py         카드뉴스 디자인 틀 (HTML/CSS → 이미지)
kit/verify.py           코드 검수와 시험
kit/revise.py           요청으로 고치기
templates/              시장 프로필 4종과 평가 기준
data/                   분석 결과, 생성 콘텐츠, 카드 이미지
docs/                   화면 캡처와 이 문서
```
